## Part 1 — Arrow bindings (docgen-excalidraw)

Goal: arrows honor `startBinding`/`endBinding` so externally-edited scenes (element moved without updating arrow points) render with arrows still attached — the exact scenario from the original spec.

**`src/model.rs`**
- New typed `Binding { element_id: String, focus: Option<f64>, gap: Option<f64>, fixed_point: Option<(f64, f64)> }` (serde camelCase: `elementId`, `fixedPoint`).
- `Element` gains `start_binding`/`end_binding: Option<Binding>` (renames `startBinding`/`endBinding`, defaults None). Round-trip tests updated (bindings now typed, no longer in `extra`).

**`src/render.rs`**
- `fn anchored_points(el: &Element, scene: &Scene) -> Vec<(f64, f64)>`: absolute points with first/last re-anchored to their bindings.
  - `fixedPoint` → `(x + fx·w, y + fy·h)` exactly.
  - Else: ray from the bound element's **center** through the stored endpoint, intersected with the shape perimeter offset by `gap` (default 1): rectangle = expanded AABB intersection; ellipse = unit-direction scaled to the boundary; diamond = ray vs the 4-edge polygon; other kinds fall back to the AABB. `focus != 0` displaces the ray origin perpendicular (`center + perp(unit) · focus · dist`) per excalidraw's algorithm.
  - Empty `points` + both bindings present → synthesize the two endpoints from the bound elements.
- The `"line" | "arrow"` arm and `emit_arrowheads` consume `anchored_points` (arrowheads follow the re-anchored tips).

**Tests** (unit): moved-rectangle (stored points stale → emitted path coordinates land on the moved edge), `fixedPoint` exactness, ellipse-bound endpoint on the boundary, binding round-trip. Then update `examples/pipeline*.excalidraw`: arrows get bindings; v2 moves a bound box **without** touching arrow points — the diff render must show the arrow following. Visual-gate the regenerated demo PDF/pptx/diff artifacts (judge agent), plus regenerate the M4 examples.

## Part 2 — M5: wasm packaging & CI

**WIT surface** — `crates/docgen-wasm/wit/docgen.wit`, world importing nothing:
```wit
package docgen:render@0.1.0;
world docgen {
  export version: func() -> string;
  export render-pdf: func(markdown: string) -> result<list<u8>, string>;
  export render-docx: func(markdown: string) -> result<list<u8>, string>;
  export render-pptx: func(markdown: string) -> result<list<u8>, string>;
  export render-diagram-svg: func(source: string, format: diagram-format) -> result<string, string>;
  export diff-docx: func(old: string, new: string, author: string, date: string) -> result<list<u8>, string>;
}
enum diagram-format { mermaid, excalidraw }
```
- `docgen-wasm` uses `wit-bindgen` `generate!` against this world; deps extended with docgen-office + docgen-excalidraw (raster feature ON so docx/pptx exports work — quick-xml/zip/resvg are all wasm-safe pure Rust). The old `#[unsafe(no_mangle)]` probe is replaced by the WIT exports.

**Feature gating for zero imports**

- `docgen-wasm`: depends on `docgen-mermaid` with `default-features = false` → wasm32-unknown-unknown core has **zero host imports** (the 5 wasm-bindgen placeholders came solely from merman's math chain).

**Component build** (per the README's sketched path): build the unknown-unknown core, then `wasm-tools component new` into a component — no WASI adapter needed because the world imports nothing.
